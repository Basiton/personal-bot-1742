# ✅ ФУНКЦИОНАЛ ГОТОВ: Импорт аккаунтов через Auth Key/tdata

## 📋 Что реализовано

### 1. Утилита конвертации `convert_session.py`

Конвертирует различные форматы в StringSession:

- ✅ **Auth Key (HEX)** → StringSession
- ✅ **tdata (Telegram Desktop)** → StringSession  
- ✅ **`.session` файлы** → StringSession
- ✅ **Поддержка прокси** для всех типов
- ✅ **Интерактивный режим** - просто запустите и следуйте инструкциям
- ✅ **Автоматическая проверка** авторизации
- ✅ **Сохранение результата** в `session_converted.json`

### 2. Команда `/addaccount` в боте

Добавляет аккаунты с полной поддержкой прокси:

```
/addaccount +номер StringSession [Имя] [прокси]
```

**Возможности:**
- ✅ Проверка валидности сессии перед добавлением
- ✅ Автоматическое получение информации об аккаунте
- ✅ Поддержка прокси (SOCKS5, SOCKS4, HTTP)
- ✅ Автоматическое определение имени из аккаунта
- ✅ Сохранение в bot_data.json
- ✅ Статус RESERVE по умолчанию
- ✅ Логирование всех операций

### 3. Обновлённая команда `/importsession`

Теперь перенаправляет на `/addaccount` с информацией о новом способе.

## 🚀 Как использовать

### Вариант 1: Интерактивная конвертация

```bash
python3 convert_session.py
```

Скрипт спросит:
1. Тип данных (Auth Key / tdata / .session)
2. Нужен ли прокси
3. Все необходимые параметры

Результат сохраняется в `session_converted.json`.

### Вариант 2: Добавление в бота

В боте выполните:

```
/addaccount +79991112233 1BVtsOHsBu7w9... Александр socks5:proxy.com:1080:user:pass
```

**Без прокси:**
```
/addaccount +79991112233 1BVtsOHsBu7w9... Александр
```

**Минимально (имя подставится автоматически):**
```
/addaccount +79991112233 1BVtsOHsBu7w9...
```

### Вариант 3: Активация аккаунта

```
/toggleaccount +79991112233
```

Статус изменится: 🔵 RESERVE → ✅ ACTIVE

## 🔐 Безопасность

### ⚠️ ВАЖНО:

1. **Auth Key = полный доступ**
   - Никому не передавайте
   - Храните зашифрованным
   - Удаляйте после конвертации

2. **StringSession = тоже сессия**
   - Это base64-кодированная сессия
   - Защищайте как пароль

3. **tdata = полная копия аккаунта**
   - Используйте только свои tdata
   - Не открывайте чужие tdata

4. **Прокси**
   - Используйте приватные прокси
   - Проверяйте на утечки
   - Разные IP для разных аккаунтов

## ❓ FAQ

### Q: Auth Key не работает, ошибка "не авторизован"

**A:** Попробуйте другой DC ID (1-5). Обычно:
- DC 1: США (Майами)
- DC 2: Европа (Амстердам) ← **по умолчанию**
- DC 3: США (Майами)
- DC 4: Европа (Амстердам)
- DC 5: Сингапур

### Q: Где найти Auth Key в Telegram Desktop?

**A:** Проще использовать tdata целиком (вариант 2). 
Auth Key находится в зашифрованном виде внутри tdata.

### Q: tdata не конвертируется

**A:** Убедитесь что:
1. Установлена библиотека `opentele`
2. Путь к tdata правильный
3. В tdata есть авторизованные аккаунты
4. Telegram Desktop был закрыт перед конвертацией

### Q: Можно ли использовать одну сессию на нескольких серверах?

**A:** Нет, сессия привязана к одному клиенту. 
Одновременный вход с разных IP приведёт к разлогиниванию.

### Q: Как удалить добавленный аккаунт?

**A:** 
```
/deauth +номер
```

## 🎯 Статусы аккаунтов

После добавления через `/addaccount`:
- 🔵 **RESERVE** - добавлен, но не активен
- ✅ **ACTIVE** - активен, используется для комментариев
- 🔴 **BROKEN** - сломан, нужна переавторизация

Переключение:
```
/toggleaccount +номер
```
