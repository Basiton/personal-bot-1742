# 🔑 Добавление аккаунтов через Auth Key или tdata

## 📋 Описание

Этот функционал позволяет добавлять аккаунты в бота **без необходимости получения SMS кода**. Вместо этого используются:

1. **Auth Key (HEX)** - 512-символьная hex строка (ключ авторизации Telegram)
2. **tdata** - папка с данными из Telegram Desktop
3. **Готовая StringSession** - из других источников

## 🚀 Быстрый старт

### Шаг 1: Получите StringSession

#### Вариант А: Из Auth Key

```bash
python3 convert_session.py
# Выберите: 1. Auth Key (HEX)
# Вставьте ваш Auth Key (512 символов)
# Укажите DC ID (обычно 2)
# Введите прокси если нужен
```

#### Вариант Б: Из tdata (Telegram Desktop)

```bash
# Установите opentele
pip install opentele

python3 convert_session.py
# Выберите: 2. tdata папка
# Укажите путь к папке tdata
# Введите прокси если нужен
```

#### Вариант В: Из .session файла

```bash
python3 convert_session.py
# Выберите: 3. .session файл
# Укажите путь к .session файлу
# Введите прокси если нужен
```

### Шаг 2: Добавьте аккаунт в бота

После конвертации вы получите файл `session_converted.json` с StringSession.

В боте выполните:

```
/addaccount +79991112233 1BVtsOHsBu7w9... Александр
```

**С прокси:**

```
/addaccount +79991112233 1BVtsOHsBu7w9... Александр socks5:proxy.com:1080:user:pass
```

## 📝 Формат команды /addaccount

```
/addaccount +номер StringSession [Имя] [прокси]
```

### Параметры:

- `+номер` - номер телефона с кодом страны (обязательно)
- `StringSession` - строка сессии (обязательно)
- `Имя` - имя аккаунта (опционально, подставится из аккаунта)
- `прокси` - прокси в формате `тип:хост:порт:юзер:пароль` (опционально)

### Примеры:

**1. Минимальный (имя возьмётся из аккаунта):**
```
/addaccount +79991112233 1BVtsOHsBu7w9MbxjS...
```

**2. С именем:**
```
/addaccount +79991112233 1BVtsOHsBu7w9MbxjS... Александр
```

**3. С прокси:**
```
/addaccount +79991112233 1BVtsOHsBu7w9MbxjS... Александр socks5:proxy.example.com:1080:username:password
```

**4. С прокси без имени:**
```
/addaccount +79991112233 1BVtsOHsBu7w9MbxjS... . socks5:proxy.example.com:1080:username:password
```
(точка вместо имени - имя возьмётся из аккаунта)

## 🌐 Форматы прокси

### SOCKS5 (рекомендуется):
```
socks5:host:port:username:password
```

### SOCKS4:
```
socks4:host:port:username:password
```

### HTTP:
```
http:host:port:username:password
```

## 🔧 Утилита convert_session.py

### Установка зависимостей:

```bash
# Для работы с tdata
pip install opentele

# Для QR кодов (опционально)
pip install qrcode pillow
```

### Использование:

```bash
python3 convert_session.py
```

Утилита интерактивно запросит:
1. Тип исходных данных (Auth Key / tdata / .session)
2. Нужен ли прокси
3. Соответствующие данные для конвертации

### Результат:

После успешной конвертации создаётся файл `session_converted.json`:

```json
{
  "phone": "+79991112233",
  "session": "1BVtsOHsBu7w9MbxjS...",
  "proxy": "socks5:host:1080:user:pass",
  "type": "auth_key"
}
```

Этот файл содержит все данные для добавления в бота.

## 📱 Как получить Auth Key?

### 1. Из Telegram Desktop

1. Откройте настройки
2. Advanced → Export Telegram data
3. В экспортированных файлах найдите `key_data` или подобное
4. Auth Key - это 256-байтный ключ в HEX формате (512 символов)

### 2. Из других клиентов

- **telegram-cli**: файл `.telegram-cli/state`
- **Pyrogram**: файл `.pyrogram/sessions/name.session`
- **Telethon**: файл `name.session` (sqlite база)

### 3. Готовые инструменты экспорта

Существуют готовые инструменты для извлечения Auth Key:
- `telegram-export-auth-key`
- `tdata-extractor`
- и другие

## 🔐 Безопасность

### ⚠️ ВАЖНО:

1. **Auth Key = полный доступ к аккаунту**
   - Никому не передавайте Auth Key
   - Храните в зашифрованном виде
   - Удаляйте после конвертации

2. **StringSession тоже даёт доступ**
   - Это та же сессия, только в base64
   - Защищайте так же, как Auth Key

3. **tdata содержит все данные**
   - Полная копия аккаунта
   - Используйте только из доверенных источников

4. **Прокси**
   - Используйте приватные прокси
   - Не используйте бесплатные публичные прокси
   - Проверяйте прокси на утечки DNS/WebRTC

## ❓ FAQ

### Q: StringSession не работает, ошибка "не авторизован"

**A:** Возможные причины:
- Сессия устарела (аккаунт разлогинен)
- Неправильный DC ID при конвертации Auth Key
- Сессия от другого API_ID/API_HASH

**Решение:**
- Попробуйте другой DC ID (1-5)
- Проверьте, что аккаунт активен
- Пересоздайте сессию заново

### Q: Прокси не работает

**A:** Проверьте:
- Формат прокси: `тип:хост:порт:юзер:пароль`
- Прокси действительно работает (проверьте в браузере)
- Тип прокси поддерживается (socks5/socks4/http)

### Q: Могу ли я использовать один прокси для нескольких аккаунтов?

**A:** Да, можно. Но для безопасности рекомендуется:
- Разные прокси для аккаунтов из разных стран
- Не более 3-5 аккаунтов на один IP

### Q: Как удалить аккаунт после добавления?

**A:** Используйте команду:
```
/deauth +номер
```

## 📊 Статусы аккаунтов

После добавления аккаунт получает статус **RESERVE** (резерв).

Для активации используйте:
```
/toggleaccount +номер
```

Статусы:
- ✅ **ACTIVE** - активен, используется для комментирования
- 🔵 **RESERVE** - резерв, не используется
- 🔴 **BROKEN** - сломан, требует переавторизации

## 💡 Советы

1. **Всегда используйте прокси для российских номеров** - меньше риск бана
2. **Храните резервные копии StringSession** - на случай проблем с сервером
3. **Не добавляйте слишком много аккаунтов сразу** - делайте паузы
4. **Проверяйте статус после добавления** - `/listaccounts`
5. **Используйте осмысленные имена** - будет проще управлять

## 🔗 Связанные команды

- `/listaccounts` - список всех аккаунтов
- `/toggleaccount` - изменить статус аккаунта
- `/deauth` - удалить аккаунт
- `/exportsession` - экспортировать сессию существующего аккаунта
- `/auth` - авторизовать новый аккаунт через SMS код (для не-российских номеров)
