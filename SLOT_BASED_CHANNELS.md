# Распределение Каналов По Слотам - ПРАВИЛЬНАЯ РЕАЛИЗАЦИЯ ✅

## Проблема

Аккаунты "прыгают" между позициями (worker 0 → worker 2 → worker 1), из-за чего один и тот же аккаунт каждый раз получает разные каналы.

**Пример проблемы:**
```
Запуск 1:
- Worker 0: Юлия → каналы 0-83
- Worker 1: Валя → каналы 84-167
- Worker 2: Маша → каналы 168-251

После ротации (порядок изменился):
- Worker 0: Валя → каналы 0-83  ❌ (были 84-167)
- Worker 1: Маша → каналы 84-167  ❌ (были 168-251)
- Worker 2: Петя → каналы 168-251  ✅ (новый аккаунт)
```

---

## Решение

**Каналы привязаны к СЛОТАМ, а не к аккаунтам!**

```
Worker Slot 0: всегда обрабатывает каналы 0-83
Worker Slot 1: всегда обрабатывает каналы 84-167
Worker Slot 2: всегда обрабатывает каналы 168-251
```

При ротации аккаунт просто **занимает слот** и получает его каналы:

```
Запуск 1:
- Slot 0 (каналы 0-83): Юлия
- Slot 1 (каналы 84-167): Валя
- Slot 2 (каналы 168-251): Маша

После ротации:
- Slot 0 (каналы 0-83): Петя  ✅ (новый, получил каналы слота 0)
- Slot 1 (каналы 84-167): Оля  ✅ (новая, получила каналы слота 1)
- Slot 2 (каналы 168-251): Маша  ✅ (осталась в том же слоте)
```

---

## Как Работает

### 1. Инициализация Слотов

При первом `/startmon` вызывается `initialize_slot_channels()`:

```python
slot_channel_assignments = {
    0: [channel1, channel2, ...],  # каналы 0-83
    1: [channel84, channel85, ...], # каналы 84-167
    2: [...],                        # каналы 168-251
    ...
}
```

**Один раз** - при запуске мониторинга. Дальше это распределение используется постоянно.

### 2. Запуск Воркера

Каждый воркер получает каналы из **своего слота**:

```python
my_channels = self.slot_channel_assignments[worker_index]
```

**worker_index** - это просто номер позиции (0, 1, 2, ...).

### 3. Ротация

При ротации:
- Старый аккаунт деактивируется (освобождает слот)
- Новый аккаунт активируется
- **Новый воркер запускается с тем же worker_index**
- Получает каналы из `slot_channel_assignments[worker_index]`

**Ничего не передаётся** - каналы уже закреплены за слотом!

## Разница С Предыдущей Реализацией

### ❌ Старая (персистентные каналы у аккаунтов)

```python
accounts_data[phone]['assigned_channels'] = [...]
# Каналы привязаны к АККАУНТУ
# При ротации каналы ПЕРЕДАЮТСЯ новому аккаунту
```

**Проблема:** Сложность, ненужная логика передачи.

### ✅ Новая (каналы закреплены за слотами)

```python
slot_channel_assignments[worker_index] = [...]
# Каналы привязаны к СЛОТУ
# При ротации аккаунт просто занимает слот
```

**Плюсы:**
- Проще и понятнее
- Нет логики "передачи" каналов
- Стабильное распределение
- Worker slot 0 всегда работает с одними и теми же каналами

---

## Важно

- **Слоты нумеруются от 0:** worker_index = 0, 1, 2, 3, ...
- **Количество слотов = количество активных аккаунтов** при первом запуске
- **При изменении max_parallel_accounts:** нужно перезапустить `/stopmon` + `/startmon` для пересчета слотов
- **Распределение НЕ сохраняется в bot_data.json** - оно в памяти и пересоздается при каждом `/startmon`
